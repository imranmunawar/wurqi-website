# Wurqi Website
## Product Requirements Document

**Product:** Wurqi Marketing Website  
**Website:** wurqi.com  
**Frontend:** Next.js  
**Architecture:** Modular, SEO-first, component-driven  
**Principles:** KISS, DRY, SOLID, Clean Architecture  
**Document Version:** 1.0  
**Target:** Modern Enterprise SaaS Website

---

# 1. Executive Summary

Wurqi is an enterprise work management platform designed to bring together work, people, communication, goals, projects, tasks, plans and organizational visibility into a unified platform.

The current Wurqi website communicates the product's core value proposition but requires a significant modernization in:

- Visual design
- Product storytelling
- Conversion optimization
- Information architecture
- SEO
- Product visualization
- Responsive experience
- Performance
- Content structure
- Enterprise positioning
- Calls-to-action
- Technical architecture

The new website should position Wurqi as a **modern enterprise work management platform**, rather than simply another project-management application.

The website should communicate:

> **Strategy → Planning → Execution → Collaboration → Visibility → Decision Making**

as one connected work-management experience.

## Major Problems to Address

### 3.1 Weak SaaS conversion funnel

The current website primarily explains Wurqi rather than guiding users toward a conversion action.

### 3.2 Limited product visualization

Enterprise software needs to be demonstrated visually.

The new website should use:

- Product screenshots
- UI mockups
- Animated workflows
- Interactive product previews
- Dashboard visuals
- Gantt examples
- Work-item relationships
- Notification examples
- Collaboration examples

### 3.3 Generic messaging

Statements such as "future of work" are broad.

The new website should emphasize measurable business outcomes:

- Improve visibility
- Reduce operational silos
- Align teams
- Track execution
- Identify risks earlier
- Improve accountability
- Accelerate decision making

### 3.4 Content/SEO opportunity

The current blog contains articles primarily dating from 2020.

The redesigned site should establish a modern SEO/content engine around work management, enterprise project management, portfolio management, OKRs, operational visibility, workflow management and related search intent.

### 3.5 Information architecture

The existing website contains multiple feature-oriented URLs and older content structures.

The new site should establish a clean, intentional URL hierarchy.

# 38. KISS Principle

Keep the website architecture simple.

Avoid:

- Unnecessary micro-frontends
- Over-engineered state management
- Excessive abstractions
- Complex dependency chains
- Client-side rendering without a reason
- Custom infrastructure where managed services are sufficient

Marketing website ≠ SaaS application.

The website should remain lightweight.

---

# 39. DRY Principle

Centralize:

- Navigation
- SEO metadata
- CTA configuration
- Button variants
- Typography
- Design tokens
- Content models
- Analytics events
- Forms
- Schema generation

Avoid duplicating the same logic across pages.

---

# 40. SOLID Principles

### Single Responsibility

Each component should have one clear responsibility.

### Open/Closed

Components should support extension through props/configuration rather than modification.

### Liskov Substitution

Reusable UI components should maintain predictable contracts.

### Interface Segregation

Do not create huge component prop interfaces.

### Dependency Inversion

Features should depend on abstractions/configuration rather than hardcoded infrastructure.

---

# 41. State Management

Avoid global state unless necessary.

Recommended:

```text
Server State
    ↓
React Server Components

Local UI State
    ↓
useState / useReducer

Complex Client State
    ↓
Zustand only if required
```

The marketing website should not introduce Redux unless there is a genuine requirement.
